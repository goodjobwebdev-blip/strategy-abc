# Предлагаемый технологический стек

Статус: инженерное предложение для следующего этапа. Текущая заглушка использует только HTML, CSS и JavaScript; игровой стек ещё не установлен.

## Рекомендация

| Задача | Технология | Причина выбора |
| --- | --- | --- |
| Игровая логика | TypeScript | Типы для отрядов, приказов и состояния облегчают развитие симуляции. |
| 2D-карта и взаимодействие | Phaser | Готовые сцены, камеры, отрисовка, ввод и игровой цикл. |
| Разработка и сборка | Vite | Локальный сервер и сборка статического приложения. |
| Меню и панели | HTML/CSS | Простые доступные панели рядом с игровым полем; отдельный UI-фреймворк пока не требуется. |
| Хостинг | GitHub Pages | Публикация статических файлов приложения. |
| Проверка симуляции | Vitest, при реализации правил | Проверки значимых игровых инвариантов и воспроизводимых сценариев. |

Phaser предоставляет WebGL/Canvas-отрисовку и определения TypeScript. Он подходит для схематичной 2D-игры, но не предоставляет готовые мораль, строй, стратегический ИИ или экономику: эти системы реализуем самостоятельно.

## Почему Phaser

Для проекта полезны готовые сцены и камеры глобальной и тактической карт, выбор отрядов указателем, масштабирование, отрисовка условных знаков и обновление состояния. Это уменьшает объём инфраструктурного кода.

Альтернатива — PixiJS с самостоятельно построенной игровой инфраструктурой. Она имеет смысл при необходимости особого контроля над рендерингом, но для первого прототипа предлагается Phaser. 3D-движок на текущем этапе не требуется.

## Отделить симуляцию от изображения

Предлагаемая будущая структура:

```text
src/
  simulation/   — состояние, приказы, столкновения, мораль, события
  ai/           — выбор приказов противником и в автобою
  scenes/       — Phaser-сцены и отображение состояния
  campaign/     — провинции, армии, переходы между ходами
  data/         — описания фракций, войск и местности
  ui/           — меню, панели и отчёты
```

Модуль simulation не должен импортировать Phaser, DOM или браузерные таймеры. Он принимает состояние и приказы и обновляется с фиксированным шагом времени. Случайность, если нужна, задаётся seed для повторяемости.

В ручном бою приказы формирует игрок и ИИ, а Phaser показывает результат. В автобою приказы формирует ИИ, а тот же расчёт работает без отрисовки. Это не обещание идентичных исходов при разных приказах: общими должны быть правила, а не заранее заданный победитель.

Физику столкновений и построений необходимо выбирать под движение отрядов; встроенный физический движок не заменяет тактическую модель. Web Worker можно добавить после измерения производительности, если ускоренный автобой блокирует интерфейс.

## Сохранения и сервер

Для первого одиночного прототипа сервер не нужен. Позднее предлагаются локальные сохранения в IndexedDB с версией формата и экспортом JSON. GitHub Pages публикует клиентские файлы; аккаунты, облачные сохранения и мультиплеер потребуют отдельного серверного решения.

## Путь публикации

Сейчас: Settings → Pages → Deploy from a branch → main → /(root). Точка входа index.html и файл .nojekyll находятся в корне репозитория. docs содержит только документацию.

После внедрения Vite: хранить исходники в src, собирать приложение в dist и публиковать через GitHub Actions. Для адреса проекта /strategy-abc/ задать Vite base: '/strategy-abc/'. Корневой index.html останется точкой входа для Vite; документы останутся в docs. В Pages потребуется сменить источник на GitHub Actions, поскольку исходники TypeScript требуют сборки. Это изменение способа публикации не меняет адрес игры и не требует переносить её в docs.

Версии зависимостей выбрать при создании игрового прототипа, проверить совместимость, зафиксировать package-lock.json и использовать npm ci в CI. Текущий Hello World не загружает библиотеки с CDN.
