# Стек и архитектура MVP

## Реализовано

- TypeScript для состояния, правил и интерфейса.
- Phaser **3.90.0** для 2D-отрисовки, ввода, масштабирования и игрового цикла.
- HTML/CSS для панелей, меню и диалогов.
- Node.js **22.18+** для автономной сборки TypeScript через `stripTypeScriptTypes`.
- Vite **7.1.12** как предусмотренный путь разработки и пакетной сборки.
- Встроенный `node:test` для проверок симуляции без установки тестового фреймворка.
- GitHub Pages, источник `main /root`, для статической публикации.
- localStorage для сохранения кампании и незавершённого боя; схема сохранения проверяется при загрузке.

## Два пути сборки

В среде первой разработки скачивание пакетов из npm было заблокировано. Поэтому официальный Phaser 3.90.0 получен из GitHub и сохранён локально вместе с MIT-лицензией. Игра не зависит от CDN.

`npm run build` работает без npm install: удаляет типы средствами Node.js, преобразует локальные импорты `.ts` в `.js`, копирует Phaser и CSS, создаёт import map и переносит готовые файлы в корень. Этот путь **не выполняет проверку типов**, поэтому проверки симуляции и интеграционные проверки остаются обязательными.

`npm run check` и `npm run build:bundle` используют TypeScript и Vite после установки зависимостей. Vite собирает `app/index.html` и исходники, затем тот же скрипт публикации переносит результат в корень. Прямые версии зафиксированы; package-lock.json пока отсутствует из-за ограничения npm и должен быть создан при доступной установке.

В текущем релизе проверена автономная сборка. Путь Vite и полная проверка типов в исходной среде не запускались.

## Отделение правил от изображения

`battle.ts`, `campaign.ts` и `data.ts` не импортируют Phaser или DOM. Симуляция боя обновляется фиксированным шагом **0,1 секунды**. В ней нет случайности: одинаковые армии и приказы дают одинаковый результат.

Ручной бой получает приказы игрока и противника. Автобой использует те же правила, но ИИ выбирает приказы за обе стороны и расчёт идёт без отрисовки. Полигон использует тот же модуль с другим набором армий.

Урон на каждом шаге применяется одновременно. Мораль учитывает потери, фланг/тыл и бегство соседей; характеристики войск, усталость, строй, лес и высота влияют на эффективность. Это упрощённая модель отрядов, не физика отдельных солдат.

`view.ts` показывает состояние через Phaser. `main.ts` связывает карту, интерфейс, результаты сражений и кампанию. `storage.ts` проверяет формат сохранения перед восстановлением; незаконченный бой восстанавливается на паузе.

## Маршруты кампании

A* использует сетку 10 единиц и проверку участков пути с шагом до 3 единиц. Нельзя пересечь море или горы вне дороги; диагональные переходы также проверяются. Дорога уменьшает стоимость движения до 52% от равнины. Алгоритм ищет путь по стоимости движения, а не только по длине.

## Публикация

Готовые файлы находятся в корневом `index.html` и `assets`. Исходная точка входа — `app/index.html`. `docs` содержит только документы.

GitHub Pages публикует записанные в main статические файлы из корня. Скрипт сборки не затрагивает документы. Для автоматической сборки исходников позже можно добавить CI и перейти на публикацию через Actions; адрес игры при этом останется тем же.
